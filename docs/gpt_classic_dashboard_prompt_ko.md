# GPT Classic 전달용 프롬프트

아래 내용을 그대로 복사한 뒤 `[질문 목록]` 부분에 실제 질문 3~4개를 넣는다. 함께 `docs/dashboard_design_handoff_ko.md`를 첨부한다.

---

당신은 B2B AI 인텔리전스 제품의 시니어 UX/UI 디자이너다. 첨부한 `TrendSparC 최종 대시보드 디자인 핸드오프`를 먼저 완전히 읽고, 그 문서에 정의된 실제 출력 계약과 금지사항을 지켜라.

TrendSparC는 사용자의 질문 및 첨부문서를 실제 웹 문서와 함께 수집·분석하여, 보고 목적과 청중에 맞는 구조화 보고서를 생성한다. 단순 뉴스 목록이 아니라 결론·근거·위험/기회·행동을 연결하는 의사결정 대시보드다.

## 이번 과업

아래 질문 각각에 대해 독립적인 최종 데스크톱 대시보드 시안을 설계하라. 질문이 4개면 4개 화면, 3개면 3개 화면을 만든다. 모든 화면은 같은 TrendSparC 디자인 시스템을 공유하되, 질문의 보고 목적과 청중에 따라 정보 구조와 컴포넌트 우선순위는 달라야 한다.

## 질문 목록

```text
1. 질문: [여기에 질문 입력]
   섹터: [자동 감지 또는 sector_id]
   청중: [executive / management / practitioner / external]
   첨부자료: [없음 또는 종류]

2. 질문: [여기에 질문 입력]
   섹터: [자동 감지 또는 sector_id]
   청중: [audience_id]
   첨부자료: [없음 또는 종류]

3. 질문: [여기에 질문 입력]
   섹터: [자동 감지 또는 sector_id]
   청중: [audience_id]
   첨부자료: [없음 또는 종류]

4. 질문: [선택]
   섹터: [자동 감지 또는 sector_id]
   청중: [audience_id]
   첨부자료: [없음 또는 종류]
```

## 반드시 지킬 조건

1. 각 질문의 예상 보고 목적을 `current_status`, `issue_response`, `future_business`, `root_cause` 중 하나로 판단하고 그 이유를 먼저 설명한다.
2. 최종 화면은 1440px 데스크톱을 기준으로 설계한다.
3. 상단에 원문 질문, 섹터, 청중, 보고 목적, 문서 수, 첨부 유무, confidence/limitations 접근점을 둔다.
4. Executive Summary는 최상위 결론으로 가장 먼저 읽혀야 한다.
5. 목적별로 섹션 순서와 컴포넌트를 다르게 설계한다.
6. `evidence`, `confidence`, `limitations`를 숨기지 않는다.
7. 네이버 뉴스는 모든 섹터의 핵심 검색 채널이지만, 근거 신뢰도는 원 발행처 기준이라는 점을 UI 정보 구조에 반영한다.
8. 첨부문서는 웹 문서와 동등한 분석 근거다.
9. 백엔드에 없는 담당자, 마감일, 진행률, 정량 위험도, 시계열 수치, 출처 URL을 실제 값처럼 만들지 않는다.
10. 실제 수치가 없으면 장식용 차트를 만들지 않는다.
11. 질문별 화면은 서로 다른 웹사이트가 아니라 하나의 제품 안에서 목적별로 적응한 결과처럼 보여야 한다.
12. SK 로고나 계열사 로고를 임의로 재디자인하지 않는다.

## 각 질문별 산출 형식

각 질문마다 아래 순서로 답하라.

1. `Purpose & Audience Interpretation`
2. `Information Architecture`
3. `Final Dashboard Composition`
   - 위에서 아래까지 실제 섹션 순서
   - 각 영역의 크기와 grid
   - 사용할 컴포넌트
   - 기본 펼침/접힘 상태
4. `Text Wireframe`
5. `Visual Direction`
   - 컬러 토큰
   - 타이포그래피
   - spacing/grid
   - 카드/표/배지/드로어 스타일
6. `Interaction & States`
   - 로딩
   - 일부 소스 실패
   - 근거 부족
   - fallback
   - 정상 완료
7. `Responsive Rules`
8. `Developer Handoff Notes`
9. `Backend Fields Used`
10. `Backend Fields Still Needed`

마지막에는 모든 질문에 공통으로 쓰는 디자인 토큰과 재사용 컴포넌트 목록을 하나로 정리하라. 모호한 “깔끔하게”, “직관적으로” 같은 표현만 쓰지 말고 픽셀·컬럼·타입 스케일·컴포넌트 상태 수준까지 구체화하라.

가능하다면 최종 결과를 Figma에서 바로 옮길 수 있는 수준의 구조로 작성하라.
